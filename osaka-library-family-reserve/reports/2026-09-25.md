- **真因（hash＝画面遷移トークンの喪失）**: 検索結果行は
  `<a class="layer-doc" href="...TifTilDetailAction.do?urlNotFlag=1&tilcod=XXX" onclick="toDetail('XXX');return false;">`
  で、**onclick が return false するため href は人のクリックでは決して使われない**。実体の `toDetail()` は
  LBForm を POST する内部遷移で、この POST が hidden の `hash` を運ぶ。サーバは POST で来た詳細ページにだけ
  新しい hash を発行し、href を直接 GET した場合（`urlNotFlag=1`＝「URLで外から入った」）は
  **hash が空のページ**を返す。`481268b` は「ページ送りで index がずれる」対策として `openResult` を
  `page.goto(href)` に変えていたため、以後すべての書誌詳細が hash 空になった。セッション自体は生きており
  （ログアウトリンクも出る）カート投入も通るが、**hash を検証するのは最後の確定 POST
  (`WOpacSmtYoyCartExecAction.do`) だけ**なので、そこで初めてログイン画面が返り「セッション切れ」に見えた。
- **証拠（保存HTMLの hash 追跡）**: 09-12 22:44 成功=`3c15ea34`／09-14 18:30 成功=`fccdd65b` は詳細もカートも
  hash あり。09-25 は詳細ページが軒並み `HASH-EMPTY` でカートへ継承され、確定でログイン画面。
  `481268b` のコミットは最後の成功実行の38分後で、今日が新コード初の週次実行だった。
  （chojo で一部カートに hash が残っていたのは、単一ヒット直行＝POST経路の本だけ無事だったため。
  バッチに1冊でも GET 経由が混ざると最終カートが汚染される。）

     POST 遷移**で詳細を開く（表示中に該当行があればその行をクリック＝人の操作と同一、無ければ
     `toDetail(tilcod)` を直接呼ぶ。いずれも `submitFlg` を解除してから実行）。ページ送りの index ずれは
