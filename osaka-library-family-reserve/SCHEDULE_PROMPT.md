# 週次実行プロンプト（Claude Code スケジュール実行用）

運用ホームは **Claude Code（claude.ai/code）のスケジュール実行**。毎週、新しいセッションが
このリポジトリの環境で起動し、以下の手順を実行する（実行時間制限がないため刻み実行は不要）。

---

大阪市立図書館の家族週次予約を実行してください。

0. **準備**: `git fetch origin claude/osaka-library-reserve-pxkjes &&
   git checkout claude/osaka-library-reserve-pxkjes && git pull` でブランチを最新化し、
   `osaka-library-family-reserve/` に移動。**CLAUDE.md を必ず読む**（設計と前回までの状況）。
   認証情報は環境変数（OML_CARD_* / OML_PASS_*）から run.sh が .env を自動生成する。
   環境変数が無ければユーザーに確認する。**.env は絶対にコミットしない。**

1. **母の予約対象の確認**: `data/mom/queue.json` には**先週のセッションが提案しユーザー確認を
   経た4冊**が入っている。そのまま今週の予約対象として使う（選び直さない）。
   queue が空・無い場合（初回など）のみ、手順5の要領でこのセッションが選書して使う。
   ※母アカウントは自身の予約で上限（15）近くまで埋まっていることがある。その場合スクリプトが
   自動で見送り処理するので queue はそのままでよい（翌週に持ち越される）。

2. **シリーズファイルの整備**: 前回レポートの「シリーズ展開待ち」があれば Web 検索で
   `data/series/{名前}.json` を作成。加えて `"complete": false` のファイルを1〜2件、最終巻まで
   追記して true にする。**巻タイトルは大阪市立図書館OPACの表記に合わせる**
   （例: 「リトルバンパイア 1 リュディガーとアントン」のように巻数の前後にスペース。
   「シリーズ名+巻数」を詰めて書くと検索でヒットしない）。

2b. **絵本ナビリストの拡充**: `data/ehonnavi_list.csv`（age,order,title,author,publisher）は
   子どもが毎週1冊ずつ読む絵本の年齢別リスト（次男=age3 / 長男=age5 / 長女=age6）。
   絵本ナビ（ehonnavi.net）の年齢別ランキング・おすすめを Web 検索し、各 age 帯に
   **正式タイトル・著者・出版社つきで**追記する（毎回2〜3冊ずつ足せば十分。order は続き番号）。
   **公文リスト(data/kumon_list.csv)に既にある本は入れない**（重複の意味が薄い。絵本ナビ独自の
   本＝公文にない絵本を優先）。出版社は予約時の版特定に使うので正確に。所蔵確認は不要
   （スクリプトが所蔵なしを自動処理する）。

3. **計画確認**: `./run.sh --all --plan-only`（数秒・サイトアクセスなし）で今週の予定を確認。
   重複や明らかな選書ミスがあれば修正してから進む。

4. **本番実行**: アカウントごとに順番に実行する（1コマンド数分で終わる。レポートは自動で1つに統合される）:
   ```
   ./run.sh --account=mom
   ./run.sh --account=chojo
   ./run.sh --account=chonan
   ./run.sh --account=jinan
   ```
   途中で失敗したアカウントは logs/ のスクリーンショットを確認し、**再実行は1回まで**。
   サイト構造変更が疑われる場合は修正せず報告する。

5. **来週の母の4冊を選書して提案**: 予約実行が終わったら、`data/mom/preferences.md` の
   選書ルールに従い、Web検索で**来週の4冊**を選ぶ。
   **まず `data/mom/wishlist.json`（ユーザーが入れた読みたい本）を最優先で拾う**
   （preferences.md ルール0参照。`verify:true` や不確実な本は Web 検索で正式タイトル・出版社を
   照合してから入れる。所蔵がなさそうな本はその週は飛ばし wishlist に残す）。wishlist で
   埋まらない分を賞ベース選書（直木賞・芥川賞・本屋大賞・山本周五郎賞・日本ミステリー文学大賞＋
   ノンフィクション枠）で補う。`data/mom/history.csv`・`state/mom/recommended.json`・
   今週予約済みは除外。queue に見送り分が残っていればそれを先頭に、合計4冊で
   `data/mom/queue.json` に書く:
   `{ "items": [ { "title": "書名", "author": "著者", "reason": "選んだ理由" } ] }`

6. **記録と報告**:
   - 変更ファイル（state/, reports/, data/）をコミットしてプッシュする
     （例: `weekly reserve 2026-07-13`）。
   - `reports/YYYY-MM-DD.md` を要約して報告: アカウント別の予約成功／失敗／スキップ理由、
     次回の開始位置。母について今週予約した本も添える。
   - **報告の最後に「📚 来週のお母さんの4冊（候補）」として手順5の4冊を
     タイトル・作家・選んだ理由つきで提示**し、こう添える:
     「読んだことがある本や感想（★1〜5）があれば返信で教えてください。
     来週月曜の予約前に差し替え・反映します」

7. **後日の返信対応**: このセッションにユーザーから返信が来たら:
   - 「◯◯はもう読んだ」→ history.csv に追記し、queue.json から外して**代わりの1冊を選書して補充**
   - 感想・評価 → history.csv と preferences.md の「最近の要望メモ」に反映
   - 更新後にコミット・プッシュする（来週月曜のセッションが git pull で引き継ぐ）

制約:
- 予約操作はスクリプト（run.sh）だけが行う。あなたがブラウザで図書館サイトを直接操作しない。
- サイトへのアクセスは丁寧に。スクリプトの再実行は1回まで。
- 予約上限・所蔵なし・予約不可版・取消予約の復帰はスクリプトが自動処理する。

---

## 付録: Cowork 等の実行時間制限がある環境で動かす場合（刻み実行）

1コマンド約45秒で強制終了される環境では、本番実行を `./run.sh --tick` に置き換え、
`TICK:DONE` が出るまで繰り返し実行する（進捗は state/_job.json に保存され、途中終了しても
続きから再開する）。ただし tick間隔が長いとログインセッション切れで失敗しやすいため、
**可能なら Claude Code スケジュール実行を使うこと**。
